# 合同日期字段优化说明

## 优化内容

### 1. 新增签订时间字段
- 数据库添加 `signed_date` 字段
- 区分签订时间和服务期限
- 签订时间：合同签字盖章的日期
- 服务期限：合同实际生效和结束的日期

### 2. 有效期显示优化
#### 改进前
- 无论是否有明确的结束日期，都显示"合同期限"
- 即使结束日期为空，也会显示"- ~ -"

#### 改进后
- 只在同时有开始和结束日期时才显示"有效期"
- 如果合同没有明确的结束日期（如长期有效），不显示有效期字段
- 签订时间单独显示

### 3. 日期字段说明
| 字段 | 说明 | 示例 |
|------|------|------|
| 签订时间 | 合同签字盖章的日期，通常在合同首页或尾页 | 2022-01-12 |
| 有效期开始 | 服务实际开始的日期 | 2022-01-12 |
| 有效期结束 | 服务结束的日期，如果没有明确结束日期则为空 | 2023-01-11 或 空 |

## 技术实现

### 数据库变更
```sql
ALTER TABLE contracts ADD COLUMN signed_date DATETIME;
```

### 后端修改
1. `backend/app/database.py`
   - Contract 模型添加 `signed_date` 字段

2. `backend/app/services/contract_parser.py`
   - `_extract_date()` 函数支持 `signed` 类型
   - 签订时间提取模式：签订、签定、签署、签约、日期等关键词

3. `backend/app/services/llm_service.py`
   - LLM 提示词添加签订日期提取要求
   - 明确区分签订日期、开始日期、结束日期

4. `backend/app/routers/contracts.py`
   - 合同上传、列表、详情接口返回 `signed_date`
   - `_merge_llm_result()` 支持签订日期合并
   - 更新接口支持 `signed_date` 字段修改

### 前端修改
1. `frontend/src/types/index.ts`
   - Contract 接口添加 `signedDate` 字段

2. `frontend/src/lib/api.ts`
   - `transformContract()` 函数处理 `signed_date` 字段

3. `frontend/src/pages/ContractDetail.tsx`
   - 基本信息卡片：
     * 添加签订时间显示（如果存在）
     * 有效期只在同时有开始和结束日期时显示
   - 编辑表单：
     * 添加签订时间输入框
     * 调整日期字段布局为三列

## 显示逻辑

### 合同详情页
```typescript
// 签订时间（如果存在）
{contract.signedDate && (
  <div>签订时间：{contract.signedDate}</div>
)}

// 有效期（只在同时有开始和结束日期时显示）
{contract.startDate && contract.endDate && (
  <div>有效期：{contract.startDate} ~ {contract.endDate}</div>
)}
```

### 编辑表单
- 签订时间、有效期开始、有效期结束三个字段并排显示
- 所有日期字段都是可选的

## 使用场景

### 场景1：普通合同（有明确期限）
- 签订时间：2022-01-12
- 有效期：2022-01-12 ~ 2023-01-11
- 显示：签订时间 + 有效期

### 场景2：长期合同（无明确结束日期）
- 签订时间：2022-01-12
- 有效期开始：2022-01-12
- 有效期结束：空
- 显示：仅签订时间

### 场景3：框架协议（只有签订时间）
- 签订时间：2022-01-12
- 有效期开始：空
- 有效期结束：空
- 显示：仅签订时间

## 测试建议
1. 上传一份有明确期限的合同，验证三个日期字段是否正确识别
2. 上传一份长期有效的合同，验证是否只显示签订时间
3. 编辑合同，测试日期字段的修改功能
4. 验证合同列表页的显示是否正常

## 注意事项
- 旧数据的 `signed_date` 字段为空，不影响显示
- 如果需要补充旧数据的签订时间，可以通过编辑功能手动添加
- LLM 会尽力区分签订时间和服务期限，但对于格式不规范的合同可能需要人工校正
