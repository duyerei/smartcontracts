# 合同解析优化方案

## 当前问题

1. **OCR只读取前10页**：长合同的附件内容可能被遗漏
2. **全文OCR成本高**：对于100页的合同，OCR所有页面耗时长、成本高
3. **关键信息分散**：合作内容可能在附件、补充协议中

## 优化方案对比

### 方案1：两阶段解析（推荐）⭐

**流程**：
1. **第一阶段**：OCR前10页 + 最后3页（签字页）
2. **LLM分析**：判断是否需要更多内容
3. **第二阶段**：根据LLM建议，选择性OCR特定页面

**优点**：
- 平衡效率和准确性
- 大多数合同只需第一阶段
- 成本可控

**实现难度**：中等

**代码示例**：
```python
def smart_ocr_pdf(pdf_path: str) -> dict:
    # 第一阶段：读取前10页和最后3页
    doc = fitz.open(pdf_path)
    total_pages = len(doc)
    
    # 读取前10页
    first_pages_text = extract_pages(doc, 0, min(10, total_pages))
    
    # 读取最后3页（签字页）
    last_pages_text = ""
    if total_pages > 10:
        last_pages_text = extract_pages(doc, max(0, total_pages - 3), total_pages)
    
    initial_text = first_pages_text + "\n\n" + last_pages_text
    
    # LLM分析是否需要更多内容
    analysis = llm_analyze_completeness(initial_text)
    
    if analysis["needs_more"]:
        # 第二阶段：根据LLM建议读取特定页面
        additional_text = extract_pages(doc, 
                                       analysis["start_page"], 
                                       analysis["end_page"])
        return {
            "text": initial_text + "\n\n" + additional_text,
            "pages_read": [0-10, total_pages-3 to total_pages, 
                          analysis["start_page"] to analysis["end_page"]]
        }
    
    return {
        "text": initial_text,
        "pages_read": [0-10, total_pages-3 to total_pages]
    }
```

### 方案2：智能目录识别

**流程**：
1. OCR前5页，识别目录结构
2. 根据目录定位关键章节（如"附件"、"服务内容"）
3. 只OCR关键章节的页面

**优点**：
- 精准定位
- 效率最高

**缺点**：
- 依赖目录格式标准化
- 不是所有合同都有目录

**适用场景**：标准化的企业合同

### 方案3：分块OCR + LLM摘要

**流程**：
1. 将PDF分成多个块（每10页一块）
2. 只OCR每块的第一页（预览）
3. LLM判断哪些块包含关键信息
4. 完整OCR选中的块

**优点**：
- 适用于超长合同（100+页）
- 成本可控

**缺点**：
- 可能遗漏跨页内容
- 需要多次LLM调用

### 方案4：PDF元数据 + 关键词搜索

**流程**：
1. 使用PyMuPDF提取PDF文本（如果是文本型PDF）
2. 关键词搜索定位关键章节
3. 只OCR图片型页面

**优点**：
- 文本型PDF无需OCR
- 速度快

**缺点**：
- 只适用于文本型PDF
- 扫描件无效

### 方案5：渐进式加载（用户触发）

**流程**：
1. 初次上传：只OCR前10页
2. 用户点击"加载更多内容"
3. 后台OCR剩余页面

**优点**：
- 初次加载快
- 用户可控

**缺点**：
- 需要用户操作
- 体验不够自动化

## 推荐实现方案

### 阶段1：快速优化（1-2天）

实现**方案1的简化版**：

```python
def extract_contract_smart(pdf_path: str) -> str:
    """智能提取合同内容"""
    doc = fitz.open(pdf_path)
    total_pages = len(doc)
    
    # 策略：
    # - 短合同（≤20页）：全部读取
    # - 中等合同（21-50页）：前15页 + 最后5页
    # - 长合同（>50页）：前20页 + 最后5页 + 中间抽样
    
    if total_pages <= 20:
        return extract_all_pages(doc)
    elif total_pages <= 50:
        text = extract_pages(doc, 0, 15)
        text += "\n\n" + extract_pages(doc, total_pages - 5, total_pages)
        return text
    else:
        # 长合同：前20页 + 最后5页 + 中间每10页抽样1页
        text = extract_pages(doc, 0, 20)
        text += "\n\n" + extract_pages(doc, total_pages - 5, total_pages)
        
        # 中间抽样
        for i in range(20, total_pages - 5, 10):
            text += "\n\n" + extract_pages(doc, i, i + 1)
        
        return text
```

### 阶段2：LLM增强（3-5天）

添加LLM判断逻辑：

```python
def llm_check_completeness(text: str) -> dict:
    """让LLM判断内容是否完整"""
    prompt = f"""
    请分析以下合同文本，判断是否包含完整的关键信息：
    
    1. 是否有明确的合作内容/服务内容？
    2. 是否有明确的付款方式？
    3. 是否提到"见附件"、"详见附录"等字样？
    
    如果缺少关键信息，请估计这些信息可能在第几页。
    
    合同文本：
    {text[:3000]}
    
    请返回JSON格式：
    {{
        "is_complete": true/false,
        "missing_info": ["合作内容", "付款方式"],
        "suggested_pages": [15, 16, 17]  // 建议读取的页码
    }}
    """
    
    return llm_call(prompt)
```

### 阶段3：完整方案（1-2周）

实现完整的两阶段解析：

1. **第一阶段**：
   - 智能分页策略
   - LLM完整性检查
   
2. **第二阶段**：
   - 按需OCR补充页面
   - 合并内容
   - 重新LLM分析

3. **用户界面**：
   - 显示"已读取X/Y页"
   - 提供"加载完整内容"按钮
   - 显示解析进度

## 成本分析

### 当前方案
- 每份合同：10页 × OCR成本
- 平均耗时：5-10秒

### 优化后（方案1）
- 短合同（≤20页）：全部OCR，耗时10-15秒
- 中等合同（21-50页）：20页OCR，耗时10-12秒
- 长合同（>50页）：30-40页OCR，耗时15-20秒

**节省**：
- 长合同节省60-70%的OCR成本
- 准确率提升（包含签字页和关键附件）
