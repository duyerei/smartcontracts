# 附件内容识别优化说明

## 问题描述
用户反馈：合同正文中提到"详见租用业务清单"，但摘要中显示"合同未提供具体产品/服务明细表相关内容"，说明LLM没有识别到附件中的明细表。

## 问题分析

### 1. OCR读取情况
- ✅ 智能分页策略正常工作，24页合同读取了20页
- ✅ 第13页包含"附件一：租用服务清单"及具体价格信息
- ✅ OCR文本包含完整的产品明细和价格

### 2. LLM采样问题
- ❌ 原采样策略：前2500字符 + 中间1000字符 + 后1500字符
- ❌ 问题：中间1000字符可能无法覆盖到附件页面
- ❌ 关键词匹配不精确：第2-4页包含"清单"、"产品"、"费用"等词，但只是提到"详见清单"，没有具体内容

## 优化方案

### 策略调整
从"模糊关键词匹配"改为"精确内容匹配"：

#### 优化前
```python
# 查找包含"附件"、"明细"、"价格"等关键词的页面
keywords = ["附件", "明细", "价格", "产品", "费用", "清单"]
for page in pages:
    if any(keyword in page for keyword in keywords):
        key_content = page[:1500]
        break
```

**问题**：会匹配到只提到"详见清单"的页面，而不是真正包含明细的页面。

#### 优化后
```python
# 优先查找"附件"+"价格数字"的组合
for page in pages:
    if ("附件" in page or "清单" in page) and ("元/" in page or "元，" in page or "价格" in page):
        key_content = page[:1500]
        break

# 如果没找到，查找包含"产品明细"、"价格明细"且有数字的页面
if not key_content:
    for page in pages:
        if any(kw in page for kw in ["产品明细", "价格明细", "费用明细", "服务清单"]):
            if any(char.isdigit() for char in page):
                key_content = page[:1500]
                break
```

**改进**：
1. 同时检查关键词和价格标记（"元/"、"元，"）
2. 确保找到的是真正包含具体数字的页面
3. 两级匹配：先找附件+价格，再找明细+数字

### 采样结构
```
前2000字符（合同开头和主要条款）
+
关键内容1500字符（包含具体价格的附件页面）
+
后1500字符（签字盖章页）
=
总计约5000字符（约7500-10000 tokens）
```

## 技术细节

### 为什么需要精确匹配？

1. **避免误匹配**：
   - 合同正文中经常出现"详见附件"、"参见清单"等引用
   - 这些页面不包含具体内容，但包含关键词
   - 需要通过价格标记（"元/"）来区分引用和实际内容

2. **提高准确率**：
   - 附件页面通常包含具体的数字和单位
   - 通过检查"元/"、"元，"等价格标记，可以精确定位
   - 减少无效采样，提高LLM识别准确率

3. **节省token**：
   - 只采样真正有价值的页面
   - 避免浪费token在引用页面上
   - 为LLM提供更精准的上下文

### 价格标记识别

常见的价格表达方式：
- `2592元/月/线` - 单价表达
- `5592元/月` - 月度费用
- `61512元/年` - 年度费用
- `400元，` - 列表中的价格

通过检查这些模式，可以准确识别包含具体价格的页面。

## 后续建议

### 1. 支持更多价格格式
可以扩展价格标记识别，支持更多格式：
```python
price_patterns = [
```
